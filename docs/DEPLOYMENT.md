# Deployment guide (all free tiers)

Order matters: database → API → web → keep-alive → seed. Allow about 30 minutes the first time.

| Service | Plan | Hosts |
|---|---|---|
| MongoDB Atlas | M0 (free, no card) | Database |
| Render | Hobby workspace, free web service | API (`apps/api`) |
| Vercel | Hobby | Web app (`apps/web`) |
| UptimeRobot | Free | Keeps the API warm |
| GitHub Actions | Free | CI, demo seeding (later: scheduled scans) |
| Supabase | Free | File storage — set up in Milestone 3 |

## 1. MongoDB Atlas

1. Create a free account → **Create cluster** → **M0 Free**. Pick **AWS / Mumbai (ap-south-1)** if offered (else Singapore).
2. **Database Access** → *Add New Database User* → password auth. Generate a long random password. Role: *Read and write to any database*.
3. **Network Access** → *Add IP Address* → `0.0.0.0/0`.
   Render's free tier has no fixed outbound IP, so an allow-list isn't possible. The strong password and TLS protect the cluster. *(Hackathon simplification — production uses Private Endpoint / VPC peering.)*
4. **Connect** → *Drivers* → copy the `mongodb+srv://…` string. Insert the password and add the database name `lams` before the `?`:
   `mongodb+srv://lams_app:<password>@cluster0.xxxxx.mongodb.net/lams?retryWrites=true&w=majority`

## 2. Render (API)

1. Push this repo to GitHub.
2. Render dashboard → **New → Blueprint** → select the repo. Render reads [`render.yaml`](../render.yaml) and proposes the `lams-api` free web service.
3. Fill the secret values it asks for:

| Variable | Value |
|---|---|
| `MONGODB_URI` | The Atlas string from step 1 |
| `DEMO_USER_PASSWORD` | Password for all demo logins (it is shown publicly on the login page, so don't reuse a real one) |
| `CORS_ORIGINS` | Leave empty (the web app uses the same-origin rewrite). Only set if you call the API from another origin. |

`JWT_ACCESS_SECRET` is generated by Render automatically. `NODE_ENV`, `NODE_VERSION`, `DEMO_MODE` and `TRUST_PROXY` come from the blueprint.

4. Deploy. When it's live, open `https://<service>.onrender.com/api/health` and expect `{"status":"ok",…}`. Then open `/api/health/ready` and expect `"database":"ok"`.
5. Note the service URL. If it isn't `https://lams-api.onrender.com` (the name may be taken), update it in [`apps/web/vercel.json`](../apps/web/vercel.json) and push.

## 3. Seed the demo data

Either:

- **GitHub Actions (recommended):** repo → *Settings → Secrets and variables → Actions* → add `MONGODB_URI` and `DEMO_USER_PASSWORD` (same values as Render). Then *Actions → Seed demo data → Run workflow*.
- **Locally:** create `apps/api/.env` with `MONGODB_URI=…` and `DEMO_USER_PASSWORD=…`, then run `npm run seed`.

Seeding is idempotent. Re-running it restores roles, masters and demo users (and signs demo users out).

## 4. Vercel (web)

1. Vercel → **Add New → Project** → import the repo.
2. **Root Directory:** `apps/web`. Framework preset: **Vite** (auto-detected). Keep the default build command (`npm run build`) and output directory (`dist`).
3. **No environment variables.** The frontend has no secrets and needs no API URL, because `/api/*` is rewritten to Render by `vercel.json`.
4. Deploy and open the URL. The login page should list the demo accounts.

## 5. Keep the API warm (UptimeRobot)

1. Free account → **Add New Monitor** → type *HTTP(s)*.
2. URL: `https://<service>.onrender.com/api/health` (hit Render directly, not through Vercel). Interval: **5 minutes**.
3. Optional: add a second monitor on the Vercel URL to see whole-stack uptime.

One always-on free service uses about 744 of the 750 free instance-hours a month. Don't add a second free Render service, or both will be suspended near month end.

## 6. Verify

- [ ] `/api/health` returns `ok`; `/api/health/ready` shows the database `ok`.
- [ ] The web login page lists 11 demo accounts.
- [ ] Sign in as *District Collector — Pune* → **Users** shows only Pune users.
- [ ] Sign in as *State Nodal Officer — Maharashtra* → Pune and Nashik users, no Uttar Pradesh.
- [ ] Reload the page while signed in → you stay signed in (refresh cookie works through the rewrite).
- [ ] Switch to हिन्दी → the interface, role names and places change language.
- [ ] `/api/docs` shows the API documentation.

## Environment variables (API)

| Variable | Required | Default | Notes |
|---|---|---|---|
| `NODE_ENV` | prod | `development` | `production` on Render |
| `MONGODB_URI` | prod | in-memory (dev) | Atlas connection string |
| `JWT_ACCESS_SECRET` | prod | dev-only value | ≥32 chars. Production refuses the dev value. |
| `DEMO_MODE` | | `true` in dev, off in prod unless set | Enables `/api/auth/demo-accounts` |
| `DEMO_USER_PASSWORD` | if demo/seed | dev-only value | Seeding a real DB requires it explicitly |
| `TRUST_PROXY` | | `0` | `2` on Render behind the Vercel rewrite |
| `CORS_ORIGINS` | | empty | Comma-separated origins for direct browser calls |
| `ACCESS_TOKEN_TTL_SECONDS` | | `900` | |
| `REFRESH_TOKEN_TTL_DAYS` | | `7` | |
| `LOGIN_MAX_ATTEMPTS` / `LOGIN_LOCK_MINUTES` | | `5` / `15` | Account lockout |
| `RATE_LIMIT_PER_15_MIN` / `LOGIN_RATE_LIMIT_PER_15_MIN` | | `600` / `20` | Per IP |
| `API_PORT` | | `4000` | Local only. In production Render's `PORT` is used. |

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| "Starting the server…" banner for ~1 minute | Normal cold start on Render free. If it happens often, check the UptimeRobot monitor is active and pointing at `/api/health`. |
| Banner turns to "server is not responding" | Check the Render logs. A config error prints `Invalid environment configuration` with the missing variable. |
| `/api/health/ready` shows `database: down` | Atlas Network Access lacks `0.0.0.0/0`, a wrong password in `MONGODB_URI` (URL-encode special characters), or the cluster is paused (resume it in Atlas). |
| Login works but a reload signs you out | The browser is calling Render directly instead of through Vercel. Use the Vercel URL. Check the rewrite destination in `vercel.json`. |
| 404 from `/api/...` on Vercel | The rewrite destination URL is wrong. Fix `apps/web/vercel.json` and redeploy. |
| Vercel build can't find `@lams/shared` | The project Root Directory must be `apps/web`, with "Include source files outside of the Root Directory" enabled (the default). Install runs at the repo root. |
| Render blueprint rejects `autoDeployTrigger` | Older blueprint spec: replace it with `autoDeploy: true`. |
| Demo accounts missing on the login page | `DEMO_MODE` isn't `true` on Render, or the database hasn't been seeded (step 3). |
| Account locked after testing | Wait 15 minutes, or re-run the seed workflow (it unlocks demo users). |
| Render services suspended near month end | More than one free service is using the shared 750 instance-hours. |
